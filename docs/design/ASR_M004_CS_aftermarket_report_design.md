## 2. CS 운영 보고와 집계 계약

### 2.1 모집단과 단위

1. 사용자가 선택한 CSV 한 개와 접수일 범위·필터를 실행 식별정보로 고정한다. 파일명 최신순으로 누적 원본을 확정하지 않는다.
2. 기본 단위는 유효 접수일을 가진 선택 범위의 원본 행이다. 전체 ES 행을 모두 고장성 A/S로 부르지 않는다. CS 대상 업무유형의 정확한 포함 목록은 Master/사용자 승인 후 적용한다.
3. 보고서에 읽은 행, 날짜 제외 행, 기간 밖 행, 업무/필터 제외 행, 최종 포함 행을 구분한다. 순차 제외 사유를 하나씩 배정하여 합계가 읽은 행과 일치하게 한다.
4. 고유 이슈 수는 비어 있지 않은 *ID 기준으로 별도 표기한다. ID 중복이면 행 수와 고유 ID 수를 구분하고 자동 중복 제거하지 않는다. ID가 없으면 파일 해시+원본 행 번호로 추적한다.
5. 현 CSV는 최신 상태 스냅샷이다. 월별 수치는 접수월 cohort의 현재 상태이지 당시 월말 잔여 건수나 해당 월 처리 완료 실적이 아니다.

완료 기준 제안: 설계 검토 단계에서는 원본 상태 분포를 기본으로 하고 `처리완료`만의 건수와 `전달 완료`를 분리한다. 단일 완료율 및 미완료 합산은 승인된 상태 사전이 생긴 후 사용한다. 현행 두 계산을 변경하는 결정은 이번 문서로 대체하지 않는다.

표시하지 않을 지표: 완료일·배정일·방문일 없는 처리 LT/단계별 병목, 과거 backlog, 설치 분모 없는 발생률, 매출·견적·수주 없는 전환율/예상매출. 라인 중단 시간은 입력 열이 존재하더라도 수집 부족 및 기존 제외 방침에 따라 권장 보고에서 제외한다.

## 3. 이슈별 후속 조치 검토표

목적은 고객 대응의 다음 확인을 놓치지 않는 것이다. 접수 원문과 담당자 판단을 분리한 검토용 Excel을 권장한다. CSV 원본을 수정하는 양식이 아니다.

| 영역 | 필드 | 출처/규칙 |
| --- | --- | --- |
| 추적 | run_id, 파일 식별값, *ID, 원본 행 번호, 접수일 | 생성 메타데이터/원본. 중복 ID는 행 번호도 필수 |
| 대상 | 고객사, LINE/공정, 로보트 NO/기종, 부품 분류 | 원본 값 그대로; 누락을 다른 열로 임의 보충하지 않음 |
| 사실 | 원본 업무유형·상태, 접수내용, 조치이력 | 요약/상세 열을 구분하고 긴 원문은 상세 시트로 연결 |

| 담당자 기록 | 검토 담당, 다음 조치, 기한, 판단, 확인일, 근거 링크 | 원본 처리사원과 별도 필드. 사본/별도 대장에 수동 기록 |

검토 상태: 미검토 → 확인 중 → 후속 조치 필요 / 추가 확인 / 대상 아님 → 검토 종료. 조치 상태: 미착수 / 진행 중 / 완료 / 보류. 검토 종료가 서비스 완료나 매출 발생을 뜻하지 않는다. 완료 처리에는 담당자·확인일·확인 근거를 요구한다.

고객 요청이 명시돼도 이미 처리/철회됐는지 최신 조치 기록으로 확인한다. 상충 기록은 추가 확인으로 남긴다. 자동 우선순위 대신 담당자 우선순위와 기한을 우선한다. 단순 건수·장비 연식으로 긴급도를 산정하지 않는다.

## 4. 애프터마켓 검토 후보 계약

### 4.1 공통 원칙

- 후보는 판매 권유 대상 확정이 아니라 확인할 기록이다. 자동 연락·견적·원본 보정은 하지 않는다.
- 최소 근거: 추적 가능한 원본 행, 후보 유형, 근거 열/원문, 고객 요청인지 내부 의견인지, 규칙 ID, 추가 확인 사항.
- 명시적 요청과 기술적 언급을 구분한다. 키워드만 있는 기록은 판매 후보에 넣지 않고 수동 확인 대기 목록으로 분리한다.
- 부정문, 과거 조치, 철회, 완료, 타 건 인용, 복합 요청, 상충 내용은 문맥 확인이 필요하다. 단순 단어 포함 검사는 확정 규칙이 아니다.
- 후보 상태는 근거 확인 필요 / 요청 근거 확인 / 보류 / 대상 아님. 담당자가 확인한 뒤에도 수요·수주 확정으로 표기하지 않는다.

### 4.2 유형별 선정·제외

| 유형 | 검토에 올릴 근거 | 제외 또는 보류 | 추가 확인 데이터 |
| --- | --- | --- | --- |
| 스페어파트 | 예비품 확보·구매·견적·교체 부품 공급 요청이 접수/조치 원문에 명시 | 부품명 언급만 있음, 이미 납품/요청 철회, 보증 무상 처리만 존재, 자산/품번 불명확, 단순 고장 빈도 | 실제 품번·호환성·수량·현재 재고·보증·요청 유효성·구매 담당 확인 |
| 개조 | 기능 변경·증설·사양 변경·개조 검토 요청의 원문 근거 | 단순 수리/복구, 추정 원인만 존재, 이미 완료/철회, 대상 설비 식별 부족, 안전 적합성 미확인 | 요구 사양·자산/도면·변경 범위·안전 검토·기술 담당 검토·고객 승인 |
| 유지보수 | 점검·정기 보전·정비/계약 문의가 원문에 명시 | 연식/반복 접수만으로 선정, 이미 수행된 점검, 계약 포함 여부 불명확, 요청 주체 불명 | 현재 계약·보전 이력·대상 설비·주기/범위·가동 조건·담당자 확인 |

분류는 승인된 규칙 사전으로만 구현을 검토한다. 후보 규칙은 예시일 뿐 현재 자동화 기능이 아니다. 한 이슈에 여러 유형이 있으면 이슈×유형 행을 허용하고 유형 합계를 고유 이슈 합계와 혼동하지 않는다. 동일 유형 중복 발췌는 근거를 연결하되 원본 행을 삭제하지 않는다.

### 4.3 집계 및 검증

후보 수, 근거 확인 대기 수, 담당자 검토 상태별 수만 집계할 수 있다. 후보 수를 매출 파이프라인, 판매 전환율, 교체 필요 대수로 표시하지 않는다. 실제 견적/수주 관리는 향후 별도 입력 계약과 승인 후 설계한다.

구현 승인 전 사람이 표시한 정답 표본으로 유형별 적중/누락을 확인한다. 부정 요청, 완료된 요청, 철회, 같은 부품의 단순 언급, 복수 유형, 원문 공란을 반드시 포함한다. 표본 규모와 허용 오탐 기준은 Master/사용자가 정하며 이번 단계에서 정확도를 주장하지 않는다.

## 5. CSV 열 계약과 품질 처리

아래는 향후 계약 제안이다. 현재 loader가 일부 열 누락을 전체 오류로 처리하는 동작을 이미 개선한 것으로 해석하지 않는다.

| 상황 | 제안 처리 |
| --- | --- |
| 열 순서 변경/추가 | 이름 기반으로 읽기; 추가 열 원본 유지, 사용 여부 기록 |
| 이름 변경 | 승인된 정확한 별칭만 적용. 유사 이름 자동 매핑·fuzzy 금지 |
| 고장유형만 존재 | 기존 승인대로 메모리에서 고장원인에 대응 |
| 고장원인과 고장유형 공존 | 기존 canonical 우선; 두 열 보존. 값 충돌 기록, 공란 자동 보충 금지 |
| DYONE/기존 열 공존 | 별개 원본 열 유지. 고객사/공정/기종별 우선순위 승인 전 병합 금지 |
| 중복 헤더/공백 정리 후 충돌 | 파서가 자동 개명하기 전에 원본 헤더 검사, 해당 매핑을 중단하고 사용자 확인 |
| 인코딩/구분자/행 너비 이상 | 읽기 조건과 오류 위치 기록. 날짜·식별 열 구조를 신뢰할 수 없으면 분석 중단 |
| 필수 열 없음 | 해당 기능 불가로 표시; 날짜가 없으면 기간 보고 불가. 0건으로 대체하지 않음 |
| 셀 미입력 | 미입력 버킷과 건수 유지. 상태 미입력을 미완료로 자동 확정하지 않음 |
| 날짜 오류 | 원본 보존, 기간집계에서 제외하며 제외 목록/건수 제공 |
| ID 누락/중복 | 행 번호와 파일 해시 추적. 고유 건수 제한, 자동 삭제·병합 금지 |
| 공란 대체 문자열 | --, #NAME? 등은 필드별 승인 규칙에 따라 공란/오류/원문값 구분; 전역 치환 금지 |

### 분석별 최소 필드

| 기능 | 필수 | 없을 때 |
| --- | --- | --- |
| 기간 접수 집계 | 접수일 | 기간 보고 중단; 구조 점검 결과만 제공 |
| 업무별 현황 | 업무유형 | 업무 분류 불가; 전체 접수 가능 |
| 상태/완료 | 상태, 승인 상태 사전(완료 지표) | 상태 분포/완료 지표 제한; 텍스트에서 상태 추론 금지 |
| 고객/설비/부품 | 각 분석의 대상 열 | 해당 분포만 제한; 기종을 설치대수 분모로 사용 금지 |
| 후속/애프터마켓 검토 | 추적 식별값, 접수 또는 조치 텍스트 | 근거 없음 표시; 후보 임의 생성 금지 |
| 제조사 클레임 | 업무유형, 제조사 | 업무 범위 불명이면 집계 보류; 제조사 공란은 미입력 |

파일 수준 가용성(열 존재)과 행 수준 완전성(값 유효)을 함께 제공한다. 현재 profile의 채워진 값 수는 유효 값 수·기술적 정확성 보증이 아니다. 품질 보완은 검토용 사본에서 기록하고 원본 CSV 수정은 별도 승인 담당자가 수행한다.

## 6. 권장 산출물

우선 권장 조합은 회의용 PDF와 검토용 Excel이다. 최종 형식은 미확정이며 구현/기존 출력 폐기 승인이 아니다.

| 형식 | 구성 | 사용 목적/제한 |
| --- | --- | --- |
| PDF | 표지·기간/범위 → 목차 → CS 접수/원본 상태 → 업무/고객/부품 분포 → 후속 조치 요약 → 애프터마켓 검토 요약 → 입력 한계 | 내부 회의용. 긴 원문은 별도 검토표로 연결. 후보는 집계·근거 확인 상태만 표시 |
| Excel | 실행정보, CS집계, 상태정의, 이슈검토, 애프터마켓검토, 제외/품질, 원문추적 | 새 검토용 workbook 제안. 기존 Excel sheet 삭제/변경 아님. 원본 영역과 담당자 입력 영역 분리 |
| PPT | 회의 목적 확정 후 요약형 선택 제공 | PDF와 숫자/정의 동일, 세부 원문 전체를 억지로 한 장에 넣지 않음 |
| Word | 대외 제출 양식/편집 필요 시 선택 | 외부 공유 시 개인정보·내부 메모·후보 검토 내용 별도 승인 필요 |
| 실행 메타데이터 | run_id, CSV hash/행/ID/date coverage, 기간/필터, 열 매핑·상태·후보 규칙 버전, 생성시각 | 형식별 동일 실행 여부 검증. 대표 기존 pair와 혼합하지 않음 |

페이지/슬라이드 수는 실제 내용·독자 결정 후 정한다. 선택 기간 접수의 현재 상태라는 기준과 제외 범위를 본문에서 명확히 한다. 원문 발췌는 로컬 검토에 한정하고 개인정보를 외부 서비스로 자동 전송하지 않는다.
